## Basics

Q: What is cryptography?
A: Using math to hide and verify information

???

So, before we get into the details.
Here's my definition of cryptography: I'd say it is the art of using math to hide and verify information.
I'm not going to get too far into *how* the math works today but suffice it to say there are some operations that rely on the fact that it's difficult to figure out the input if you only have the output, and you can layer things to do more advanced operations on top of data while keeping those inputs secret.

---

### Randomness

- ❌ `float = Math.random()` - fast
- ✅ `crypto.getRandomValues(typedArray)` - secure

???

Before you can start hiding inputs you need sources of randomness to make it hard to guess what those inputs might have been in the first place.
Developers watching this might have made use of randomess for graphics or shuffling, but the default API for it, `Math.random()`, is actually "psuedo-random" and produces numbers that can be guessed if you know the randomness algorithm.
For cryptographic uses you need to use the special `crypto.getRandomValues` API which fills an array buffer with actual random values which are generated by the operating system.
The tradeoff is that actual randomness is slower to get, so for cases where security isn't as important, `MAth.random()` is the way to go.
The other difference is that the crypto API is specifically aimed for filling in buffers rather than returning one value at a time.

### Hashing

`hash('hello') === Uint8Array(????)`

???

The other way to get inputs for data is to use hash digests.
A hash function takes some data, and spits out a random looking buffer of data called the hash.
The math makes is so you can't recover the original input, but the same data will always yield the same hash.
This can be useful to verify data when loading it from an untrusted source by getting just the hash from a trusted source and verifying after.
Hashes are usually just a few bytes long so no matter how big the data is you can allocate a fixed size for the hash.

### Cryptographic Keys

- `encryptionKey` - Secret used to lock/unlock data
- `secretKey` - Something you keep to yourself
- `publicKey` - Something you share with others (sign, derive)
- `keyPair` - Entwined public+secret keys
- `derivedKey` - A secret key made from non-random information
- `salt` - Some random data that's added to your keys

???

These primitives in turn get used for "cryptographic keys".
Keys are just fixed size buffers of data that are plugged into crypto functions and have specific purposes.
Secret keys can be used as password to encrypt some data or as a secret only you can use for certain algorithms
Public keys are something you share publicly or with other parties.
Key pairs are made by combining a secret and public key such that operations done with the secret key can be verified with the public key, or operations on the public key can only be usable if you also have the secret key.
Some keys can be "derived" from other sources of data like hashes of passwords or algorithms using key pairs.
Lastly, some algorithms use a public bit of data called the "salt" which is a bit of randomness sprinkled beside regular data to make it harder for attackers to precompute data and guess what your non-salted data would be.

### Signatures (Sign/Verify)

- Make a key pair
- `sign(privateKey, data) -> signature`
- `verify(publicKey, signature, data) -> isValid`
- e.g. `sign(hash(socialMediaPost))`

???

So! Now that we have that out of the way, one common operation is to verify data with signatures.
You start by making a keypair, sharing the public key with whoever might want to verify you signed something.
You use your private key to generate a signature of some data.
Then anyone else can take your public key, the data, and verify you signed it.
If you keep your private key private you can prove that only you could have made that signature.
This can be useful to validate that somebody authored some content or verified it themselves.

---

### Example - Signatures

```javascript
const algo = {name: "Ed25519"}
const extractable = true
const uses = ["sign", "verify"]
const keyPair = await crypto.subtle.generateKey(algo, extractable, uses)

### Encryption

- Make a secret key
- `encrypt(secretKey, data) -> cipherText`
- `decrypt(secretKey, cipherText) -> data`
- e.g. encrypt notes before saving to disk

???

Another common ability is to encrypt data with a secret key into cipher text, and to decrypt it back from the cipher text using the secret key.
It's important to make sure the key cannot be guessed, and if that's the case you can store the ciphertext wherever you want while keeping its contents secret.
This can be useful for apps where you want data to be safe from thir parties or malware such that only the user, or set of users, has access to it.
The ciphertext is usually a bit bigger than the raw data and it can take a bit more time to decrypt and view the data compared to storing it raw.

---

### Example - Encryption

```
const keyAlgo = { name: "AES-GCM", length: 256}
const extractable = true
const uses = ["encrypt", "decrypt"]
const encryptionKey = crypto.subtle
  .generateKey(keyAlgo, extractable, uses)
const iv = crypto.getRandomValues(new Uint8Array(16));
const data = new TextEncoder().encode("Hello, world!");
const algo = { name: "AES-GCM", iv }
const cipherText = await crypto.subtle
  .encrypt(algo, encryptionKey, data);
// Share encryptionKey, iv, cipherText
const decrypted = await crypto.subtle
  .decrypt(algo, encryptionKey, cipherText)
```

### Shared secrets (Diffie Hellman Key Exchange)

- User A makes a keypair
- User B makes a keypair
- Exchange public keys
- `derive(A.privateKey, B.publicKey) -> encryptionKey`
- `derive(B.privateKey, B.publicKey) -> encryptionKey`

---

### Example - Shared Secret

```
const extractable = true
const uses = ["encrypt", "decrypt"]
